# Employment Factors Post-Processing

This backend derives direct employment results after an OSeMOSYS simulation has
finished. The calculation is ex-post: it does not affect the optimization
objective, constraints, solver status, or feasibility.

## Source Data

Employment factors and technology assumptions are loaded from:

```text
https://github.com/DEA-GE/colombia-employment-factors
```

The backend uses:

```python
from colombia_employment_factors import (
    get_model_employment_factors,
    get_technology_assumption,
)
```

`get_model_employment_factors()` provides yearly direct employment factors for
2024-2055. The factors have already been projected by the package methodology,
including decline/productivity assumptions where applicable.

`get_technology_assumption(technology)` provides:

- `construction_time_years`
- `lifetime_years`
- source metadata for those assumptions

The current backend uses construction time for annualizing construction and
manufacturing employment. Lifetime is retained in row metadata for traceability
and future lifecycle metrics, but it is not used in the main in-horizon outputs.

## Technology Mapping

The runtime mapping lives in:

```text
backend/app/services/employment_factors_mapping.yaml
```

Each OSeMOSYS technology maps to one or more employment-factor technologies.
The `multiplier` field is the MW of employment-factor technology represented by
one MW of model technology.

Example:

```yaml
PWRSOLUGE_BAT:
  components:
    - employment_technology: Utility-scale solar PV
      multiplier: 1.0
    - employment_technology: Battery storage (grid)
      multiplier: 0.6
```

For `PWRSOLUGE_BAT`, one MW of model capacity is treated as one MW of
utility-scale solar PV plus 0.6 MW of grid battery storage. The component
employment values are summed into one output row for the model technology, while
component metadata remains available in `index_json`.

## Input Capacity Variables

Only model-period installations from 2025 onwards are counted.

`NewCapacity` is used for construction and manufacturing:

```text
Employment_FTEyear_ConsManu_Direct =
    NewCapacity_MW * Construction&Manufacturing direct factor
```

`AccumulatedNewCapacity` is used for O&M:

```text
Employment_FTE_OM_Direct_Annual =
    AccumulatedNewCapacity_MW * O&M direct factor
```

`TotalCapacityAnnual` is intentionally not used for employment factors. It
includes residual capacity from the last historical year, 2024. Using it would
estimate O&M employment for the whole installed system, while this workflow
estimates employment generated by capacity additions from the optimization
period.

## Unit Conversion

OSeMOSYS capacity outputs in this repository are treated as `PJ/year`. The
employment factors use MW. Capacity is converted before applying factors:

```text
1 GW = 31.5576 PJ/year
MW = PJ/year * 1000 / 31.5576
```

## Unit Harmonization

Raw construction/manufacturing and O&M outputs are not directly comparable:

| Phase | Factor unit | Output after multiplication | Interpretation |
|---|---:|---:|---|
| Construction and manufacturing | FTE-year/MW | FTE-year | One-off labor attached to a construction cohort |
| O&M | FTE/MW | FTE | Annual workforce sustained by operating capacity |

For annual employment charts, construction/manufacturing FTE-years are spread
uniformly over the construction period from the technology assumptions package.
O&M is already annual and is not annualized.

For a plant commissioned in year `y` with construction time `d`:

```text
construction interval = [y - d + 1, y]
annual C&M FTE during construction = C&M FTE-year / d
```

The implementation supports fractional construction times. It allocates C&M
employment according to the fraction of the construction interval overlapping
each model year. The allocated annual values sum back to the original C&M
FTE-year total.

Example with an integer construction time:

```text
Commissioning year: 2030
C&M labor: 1,000 FTE-year
Construction time: 5 years

Annualized C&M FTE:
2026: 200
2027: 200
2028: 200
2029: 200
2030: 200
```

For early model-period commissioning years, some construction effort can fall
before 2025. The main annual chart keeps only in-horizon years. Pre-2025
construction labor is stored separately as:

```text
Employment_FTEyear_ConsManu_Direct_PreHorizon
```

This avoids silently dropping the labor while also avoiding the creation of
fake historical annual model outputs.

## Persisted Variables

Derived rows are stored in `osemosys.osemosys_output_param_value` with the same
simulation job id as the rest of the model outputs.

The employment variables are:

```text
Employment_FTEyear_ConsManu_Direct
Employment_FTE_ConsManu_Direct_Annualized_InHorizon
Employment_FTEyear_ConsManu_Direct_PreHorizon
Employment_FTE_OM_Direct_Annual
Employment_FTE_Total_Direct_Annual_InHorizon
Employment_FTEyear_OM_Direct_Cumulative_InHorizon
Employment_FTEyear_Total_Direct_Cumulative_InHorizon
```

### Variable Meanings

`Employment_FTEyear_ConsManu_Direct`

: Original direct construction/manufacturing result in FTE-year, attributed to
  the commissioning year of `NewCapacity`.

`Employment_FTE_ConsManu_Direct_Annualized_InHorizon`

: Direct construction/manufacturing annual FTE allocated over construction
  years that are inside the model horizon.

`Employment_FTEyear_ConsManu_Direct_PreHorizon`

: Direct construction/manufacturing FTE-year associated with model-period
  capacity additions but allocated before 2025 by the construction-time spread.

`Employment_FTE_OM_Direct_Annual`

: Direct annual O&M FTE from cumulative new capacity in each model year.

`Employment_FTE_Total_Direct_Annual_InHorizon`

: Annual comparable direct employment:

```text
Employment_FTE_ConsManu_Direct_Annualized_InHorizon
+ Employment_FTE_OM_Direct_Annual
```

`Employment_FTEyear_OM_Direct_Cumulative_InHorizon`

: Cumulative in-horizon direct O&M FTE-year, calculated as the running sum of
  annual O&M FTE over model years.

`Employment_FTEyear_Total_Direct_Cumulative_InHorizon`

: Cumulative in-horizon direct total FTE-year, calculated as the running sum of
  total annual direct FTE over model years.

## Dimensions and Disaggregation

Employment rows remain disaggregated by:

- simulation job;
- region;
- model technology;
- year;
- employment variable;
- job type;
- phase/factor type.

Composite technologies keep component metadata in `index_json`, including:

- employment-factor technology;
- component multiplier;
- converted component capacity in MW;
- factor value and unit;
- factor source;
- construction time and lifetime assumptions;
- construction allocation metadata for annualized C&M rows.

This allows downstream charts to show either:

- model-technology totals, such as `PWRSOLUGE_BAT`; or
- component details, such as solar PV and grid battery contributions inside
  `PWRSOLUGE_BAT`.

## Reporting Guidance

Use `Employment_FTE_Total_Direct_Annual_InHorizon` for annual employment charts.
It is the comparable annual FTE metric.

Use `Employment_FTEyear_Total_Direct_Cumulative_InHorizon` for milestone charts
such as cumulative employment by 2030, 2035, or 2040.

Keep `Employment_FTEyear_ConsManu_Direct` available for audit because it is the
direct output of multiplying `NewCapacity` by the construction/manufacturing
factor before annualization.
